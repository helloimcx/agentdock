# Device And Workspace Registry

This Phase 0 draft defines the ownership and contract direction for workspace and device registries.

## Workspace Registry

The workspace registry is already implemented as Local AI Core durable state.

Contract direction:

- `workspaceId`: stable id.
- `displayName`: user-facing name.
- `path`: local workspace path on the owning device.
- `defaultRuntimeId`: optional preferred runtime.
- `git`: branch, remote, dirty state, and last commit summary when available.
- `health`: `healthy`, `warning`, or `error` with actionable issues.
- `lastActiveTaskId`: optional pointer to the most recent task.
- `createdAt`, `updatedAt`, `lastOpenedAt`.

Rules:

- Local AI Core owns registry persistence.
- Renderer can create, update, delete, and list through APIs.
- Git metadata is best-effort and must not block workspace listing.
- Missing paths should degrade to health warnings or errors, not crashes.

## Device Registry

The device registry is not implemented yet. It should follow the same Local AI Core ownership model.

Draft contract direction:

- `deviceId`: stable local id generated by Local AI Core.
- `displayName`: user-facing device name.
- `kind`: `desktop`, `mobile`, `server`, or `unknown`.
- `platform`: operating system and app platform metadata.
- `trustStatus`: `local`, `paired`, `revoked`, or `unknown`.
- `presenceStatus`: `online`, `offline`, `sleeping`, or `unknown`.
- `capabilities`: supported control actions, such as task viewing, approval resolution, or local runtime hosting.
- `lastSeenAt`: most recent trusted contact timestamp.
- `createdAt`, `updatedAt`.

Rules:

- Pairing must be explicit.
- Device trust is separate from network reachability.
- Mobile starts as a companion control surface, not a full remote IDE.
- Device actions must be permission-scoped and audit-ready.

## Future API Shape

Reserved device APIs:

- `GET /api/local/v1/devices`
- `GET /api/local/v1/devices/:deviceId`
- `POST /api/local/v1/devices/pairing`
- `POST /api/local/v1/devices/:deviceId/revoke`

Workspace APIs are implemented in [Workspace Task Model](workspace-task-model.md).
